Q1: Why choose Zustand over Redux Toolkit or React Context? State Management

Answer: In a high-frequency canvas UI like React Flow, dragging nodes, selecting edges, and panning triggers dozens of state mutations per second. React Context causes full-tree re-renders on any context value change. Redux Toolkit introduces heavy boilerplate with actions and reducers.

Zustand provides:

  • Atomic Subscriptions: Components only re-render if their selected state slice changes (e.g. useFlowStore(s => s.selectedNodeId)).
  • External Access: useFlowStore.getState() allows the async DAG execution engine (dagRunner.ts) to read and mutate node status outside React's render loop without hooking into component lifecycles.
🎯 Interviewer Focus: Proves you understand re-render optimization and decoupling business logic from UI frameworks.
Q2: How does the DAG runner handle condition branches and dead code paths? Graph Algorithms

Answer: Condition nodes expose dual output handles: true and false. When a condition evaluates:

  1. The rule engine tests against the incoming payload (e.g. sentiment === 'positive').
  2. The runner checks the outgoing edges from that condition node.
  3. For any edge where sourceHandle !== outcome, the target node is added to a skippedNodes set.
  4. The engine recursively traverses downstream edges of skipped nodes to prune the entire inactive subtree.
  5. Skipped nodes are marked idle with "Branch not taken", avoiding wasted API calls and token costs.
// dagRunner.ts snippet if (sourceNode?.type === "condition" && edge.sourceHandle !== conditionOutcome) { skippedNodes.add(node.id); edges.filter(e => e.source === node.id).forEach(e => skippedNodes.add(e.target)); }
Q3: How do you prevent circular dependencies (cycles) in visual graphs? Graph Algorithms

Answer: We perform a pre-flight validation pass before executing. We construct an adjacency list and run DFS with a recursion stack (three-color marking):

function dfs(nodeId: string) { visited.add(nodeId); recursionStack.add(nodeId); for (const neighbor of adj.get(nodeId) || []) { if (!visited.has(neighbor)) dfs(neighbor); else if (recursionStack.has(neighbor)) hasCycle = true; } recursionStack.delete(nodeId); }

If recursionStack.has(neighbor) is true, a back-edge exists. The runner aborts execution immediately with a clear error badge before any API calls fire.

Q4: Why use Kahn's algorithm for Topological Sorting? Graph Algorithms

Answer: Kahn's algorithm operates on in-degrees (the count of incoming dependencies per node):

  1. Calculate in-degree for all nodes; enqueue nodes with inDegree === 0 (e.g. Triggers).
  2. Dequeue a node, add it to execution order, and decrement the in-degree of all target neighbors.
  3. When a neighbor's in-degree drops to 0, it enters the execution queue.

This guarantees that every node is only executed after 100% of its upstream inputs have completed and published their output payloads.

Q5: How is the multi-provider LLM adapter designed? LLM & Integration

Answer: We use an Adapter Pattern in llmService.ts. The engine accepts a unified LLMRequestParams interface and routes to specialized provider handlers:

  • OpenAI / Groq: Formats to /v1/chat/completions with system and user messages.
  • Anthropic Claude: Formats top-level system prompt and passes anthropic-dangerous-direct-browser-access header for client-side evaluation.
  • Google Gemini: Formats contents: [{ parts: [...] }] to v1beta/models/...:generateContent.
  • Local Ollama: Connects to http://localhost:11434/api/chat.

All providers normalize output into { text, data, tokensUsed, durationMs, providerUsed }.

Q6: How do you handle error boundaries and failures mid-execution? Resilience & Scale

Answer: Each node execution is wrapped in an isolated try/catch block:

  1. If an HTTP 429 (rate limit) or script error occurs, duration and error messages are captured.
  2. The node's visual badge turns red (error state) with a contextual tooltip.
  3. The step is appended to useExecutionStore logs.
  4. Execution terminates cleanly, preventing corrupt or null data from propagating downstream.
Q7: How do you safely execute custom user JavaScript in the Transform node? Resilience & Scale

Answer: We construct an isolated function execution scope using new Function("input", "context", userCode).

The code must declare function transform(input, context). It executes with access only to the immediate input and execution context map, protecting component state and catching runtime errors before they crash the UI.

Q8: How did you optimize React Flow canvas performance with 50+ nodes? State Management

Answer:

  • Memoization: All custom node wrappers (BaseNodeWrapper) are wrapped in React.memo with custom comparison checks so moving Node A does not re-render Node B.
  • Debounced Persistence: Canvas edge and position updates are held in memory and debounced before serializing to localStorage.
  • Separation of Concerns: Visual physics state is separated from execution telemetry logs in two distinct Zustand stores.
Q9: What is the Mock Mode and why is it important? LLM & Integration

Answer: Mock Mode allows offline testing, sandbox development, and live interviews without requiring paid API keys or burning inference tokens.

The mock engine analyzes prompt keywords (e.g. "sentiment", "summary", "extract") and produces realistic JSON/Markdown responses with simulated 400-600ms network latency and realistic token counts.

Q10: How would you scale this engine to run headlessly on a backend? Resilience & Scale

Answer: Because the graph definition is 100% serializable JSON (nodes and edges), the core engine files (dagRunner.ts and variableResolver.ts) are completely decoupled from React DOM.

The exact same algorithms can run on a Node.js / BullMQ worker queue or AWS Lambda. The frontend submits the workflow JSON; the backend executes the DAG and streams progress back via Server-Sent Events (SSE) or WebSockets.

Q11: How does variable interpolation resolve deep nested JSON paths? Graph Algorithms

Answer: In variableResolver.ts, we parse tokens like {{node_1.output.summary.score}}:

  1. Extract target node ID (or alias trigger / previous).
  2. Retrieve the node's output object from the global execution context map.
  3. Use a safe reduce traversal (getNestedValue) to walk the path key-by-key.
  4. If the target value is an object, serialize as formatted JSON; if primitive, cast to string.
Q12: What was the hardest bug you solved while building this project? Resilience & Scale

Answer: When an upstream LLM node produced a stringified JSON string rather than a native object, downstream condition nodes and variable resolvers attempting dot-path access failed with undefined.

I resolved this by enhancing getNestedValue to automatically attempt safe JSON parsing if dot-path traversal is requested on a string primitive. I also added support for relative reference aliases (previous.output and trigger.output), improving workflow authoring UX and preventing runtime crashes.
